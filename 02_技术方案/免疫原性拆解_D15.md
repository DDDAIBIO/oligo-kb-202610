## 0. 今天要带走的一句话

**先天免疫传感器认的不是"药"，是"模式"**（dsRNA 长度、GU-rich、CpG、5′-三磷酸）。模式可以枚举 → 模式可以从序列算出来 → **免疫原性风险可以写成函数**。今天就是把 9 条特征从"清单"冻结成"函数签名"，明天 D16 直接照规格写代码。

## 1. 传感器速记表（读笔记 §6 后，合上资料默写这张表）

| 传感器 | 识别什么 | 在核酸药里何时被触发 |
|---|---|---|
| TLR3 | 长 dsRNA | IVT 反应残留 dsRNA 杂质 |
| TLR7/8 | ssRNA，GU-rich / U-rich | 未修饰 RNA、特定基序 |
| **TLR9** | 未甲基化 **CpG DNA** | ⭐ **gapmer 的 DNA gap 里可能就有 CpG** |
| RIG-I | 5′-ppp / 5′-pp | 未加帽的 IVT 产物 |
| PKR | dsRNA | 磷酸化 eIF2α → 翻译关停 |
| 补体（替代途径） | PS 过多（抑制因子 H） | PS 铺满的初代 ASO |
| 抗 PEG 抗体 / ABC | PEG | 重复给药 → 加速血液清除 |

**三个记忆锚**：

1. **传感器认的是模式，不是分子**。同一个 CpG，在 DNA gap 里是 TLR9 配体；甲基化后（mCpG）就不是了。所以"免疫原性"能被**序列层面**的规则描述。
2. ⭐ **药效必需区 = 免疫风险区（TLR9 的两难）**：gapmer 的 DNA gap 是 RNase H1 识别的前提，也是 TLR9 扫描的对象。**你不能靠"删掉 gap"解决免疫原性**——只能靠计数、预警、设计时避开 CpG 密集的 gap 序列。这是一个天然的**多目标约束优化**问题（药效 vs 免疫原性），也是你简历上最好讲的故事之一。
3. **化学修饰能躲传感器，躲不掉抗体**。m1Ψ 躲 TLR7/8 和 RIG-I（蛋白按"模式"识别核酸），但 PEG 被抗 PEG 抗体识别（按"分子"识别）、PS 太多抑制因子 H（按"化学性质"识别）。**两类免疫原性要分开建模**：序列层（第 1–7 条特征）vs 化学/配方层（第 8 条 + PS 分布 + PEG）。

## 3. ⭐ 核心交付：9 条特征 → 函数签名（D16 的输入规格，今天冻结）

下面每条给出：函数名、输入、返回、实现提示、**边界坑**。明天照这张表写，不再讨论"该算什么"。

| # | 特征 | v0 函数签名 | 实现提示 | 边界坑 |
|---|---|---|---|---|
| 1 | CpG 计数 | `count_cpg(annotated) -> int` | 只在 **DNA 区段**内数 `CG` 相邻对 | ⭐ 跨区段边界的 CG 要单独处理（翼 RNA 的 CG 不算——TLR9 认未甲基化 **DNA**） |
| 2 | GU/U-rich 基序 | `find_gu_motifs(seq) -> list[(motif, pos)]` | v0 硬编码小表：`GUCCUUCAA`、`UGUGU`、连续 `U`≥3 | motif 表是开放的——v0 注明"最小表"，别假装完备 |
| 3 | AU-rich 元件 | `find_au_rich(seq) -> list[pos]` | 搜 `AUUUA` | 与特征 2 可能重叠命中，各自报告不合并 |
| 4 | 5′ 三磷酸 | —— **v0 跳过** | 不是序列特征，是工艺特征（IVT 加帽率） | ⭐ **设计决定**：序列打分器管不了工艺，记录为"层外变量"，将来归配方/QC 模块 |
| 5 | 双链区预测 | `max_self_complement(seq) -> int` | v0：滑动窗口找最长自互补区（8-mer 窗口） | **不是**真折叠预测（RNAfold 是阶段二）；注释里写明"粗筛" |
| 6 | GC 含量 / Tm | `gc_content(seq) -> float`、`tm_basic(seq) -> float` | 基础 Wallace 规则即可 | ⚠️ 修饰 ΔTm 修正**暂缺**（D11 欠账）→ v0 用未修正值 + 显式 TODO，别静默忽略 |
| 7 | 发夹 / 自二聚体 | `find_hairpins(seq) -> list` | v0：4–8 nt stem + 4 nt loop 的简化模式 | 同特征 5，粗筛定位，不算结构 |
| 8 | PS 计数与分布 | `ps_profile(annotated) -> dict` | 返回 `{total, per_position or per_region}` | ⭐ **必须有区段注释**——光给字符串序列无法知道哪些位置是 PS |
| 9 | poly-purine / G4 倾向 | `g_quartet_tendency(seq) -> int` | v0：连续 ≥4 个 G 的 run 计数 | 同样是粗筛；真 G4 预测在阶段二 |

**两个全局决定（比 9 条函数本身更重要）**：

- **输入格式 = 注释化序列**：`(sequence, annotations)`，annotations 形如 `{"mod": {"2MOE": [0,4,15,19]}, "ps": [...], "regions": {"gap": (5,14)}}`。这正是 D16 脚本叫 `oligo_decorate.py` 的原因——**先解析修饰注释，再打分**。纯字符串序列在真实药物上必崩（第 8 条直接无从下手）。
- **v0 只做"逐条报告"，不做加权打分**。9 个数字各自输出，怎么融合成单一风险分属于 v1（需要真实数据定权重，拍脑袋权重是伪科学）。**明天别顺手加权**，忍住。

## 4. 10 min 练习：手算一遍，你才知道函数该怎么写

用一条**合成的** 5-10-5 gapmer 练习（⚠️ 演示用，非任何真实药物序列——公开 label 里没有序列，这是事实，不是保密）：

```
区段注释：
  wing 5′（2′-MOE RNA）: C G U A C
  gap（DNA）           : T C G A T C G T A A
  wing 3′（2′-MOE RNA）: U G U A C
  PS：仅首尾各 1 个（v0 简化）
```

**任务**（先自己算，再展开答案）：

1. 全序列 CpG 计数？只在 gap 里数呢？
2. GU/U-rich 基序命中几个？位置在哪？
3. 这条序列过 TLR9 风险筛查吗？过 TLR7/8 吗？
4. 为什么这个问题必须带着区段注释才能算？（提示：特征 1 和 8）

<details>
<summary><b>参考答案</b></summary>

1. 全序列相邻 `CG` 共 **3** 处：gap 内 2 处（`T**CG**AT**CG**TAA`）+ 5′ 翼开头 1 处（`**CG**UAC`）。**只在 gap 数 = 2**。翼的 CG 是 2′-MOE RNA，不是未甲基化 DNA，不算（TLR9 认 DNA）。另查跨边界：5′翼尾 `C`+gap 首 `T` = "CT" 非 CpG；gap 尾 `A`+3′翼首 `U` = "AU" 非 CpG。答案 **2**。
2. `UGU` 命中 1 处（3′ 翼开头，位置 16–18）；`GUCCUUCAA` 未命中；连续 U≥3 未命中 → **1 处**。
3. TLR9：CpG=2，**中低风险，但报出来**（数量本身不致命，报给设计者决定）；TLR7/8：仅 `UGU` 1 处弱命中，低风险。**v0 只报告计数，不说"安全/危险"**——单一风险分是 v1 的事。
4. 特征 1：CpG 只数 DNA gap，没有注释就分不清哪些 CG 是 DNA；特征 8：PS 位置信息完全在注释里。**纯序列字符串在真实药物上必崩**——这也是 D16 测试用例第 5 个（含 `I` 等修饰字母）防的同一个坑：字母表和注释都要扩。
</details>

## 5. 回连两条旧线（2 min，防知识碎片化）

- **D3 的 ESC+**：guide 第 2 位放 2′-OMe，教材说法是钝化种子区介导的 miRNA-like 脱靶。今天多一层理解：**2′-OMe 同时也是 TLR7/8 的钝化修饰**（TLR7/8 扫 U-rich ssRNA，2′-OMe 化的糖让"模式"不再被认）。一个修饰，两个收益——"修饰清单"和"免疫风险表"是同一张矩阵的两列。
- **D4 的 m1Ψ**：全替代 U = 把 TLR7/8 最爱扫的 U 大面积换成 m1Ψ + 同时躲 RIG-I/PKR。免疫躲避是 mRNA 五大元件之外"第六大设计对象"的真正原因。

## 7. 自检（合上资料能答才算过关）

<details>
<summary><b>1. 为什么说 gapmer 的 DNA gap 是"药效必需区 = 免疫风险区"？</b></summary>

RNase H1 只识别 RNA-DNA 杂合双链 → gap 必须是 DNA；TLR9 只识别未甲基化 CpG **DNA** → gap 里的 CpG 正好是它的配体。删 gap = 药效没了；留 gap = TLR9 风险在。所以只能计数预警 + 设计期避开 CpG 密集序列，这是**约束**不是可消除的 bug。
</details>

<details>
<summary><b>2. 为什么特征 4（5′-三磷酸）今天决定从 v0 里踢出去？</b></summary>

它不是序列的属性，是工艺的属性（IVT 加帽率、纯化残留）。序列打分器的输入是注释化序列，拿不到工艺信息；硬塞进去只会得到恒为 0 的假特征。**承认工具边界、把特征归到对的层**，比"9 条凑齐"重要。将来它归 QC/配方模块。
</details>

<details>
<summary><b>3. 为什么 v0 不做加权打分，只逐条报告？</b></summary>

融合成单一风险分需要各特征的真实权重，权重只能从带标签数据学（哪些序列真的触发了免疫反应），v0 没有数据。拍脑袋加权 = 把伪科学写进代码，还会污染下游所有分析。**先让每个数字诚实，再学融合。**
</details>

<details>
<summary><b>4. m1Ψ、2′-OMe、PS、PEG 各自针对哪类免疫风险？哪些是"序列层"哪些是"配方/化学层"？</b></summary>

| 修饰 | 针对风险 | 层 |
|---|---|---|
| m1Ψ | TLR7/8、RIG-I、PKR | 序列/碱基层 |
| 2′-OMe（ESC+ 第 2 位） | miRNA-like 脱靶 + TLR7/8 | 序列/糖层 |
| PS 过多 | 补体替代途径（抑制因子 H）、蛋白结合 | 化学/骨架层 |
| PEG | 抗 PEG 抗体 → ABC | 配方/偶联层 |

序列打分器只能管前两行；后两行靠"注释"（PS 位置、是否含 PEG）带入——又是输入格式决定一切。
</details>

<details>
<summary><b>5. 明天 D16 的验收是什么？</b></summary>

`oligo_decorate.py` 对 5 个测试用例全部输出 9 条特征报告：① 纯合成 gapmer（本页 §4 的例子，手算值 = 程序值）② Patisiran 双链（注意双链合算 + 无 PS 的特殊情况）③ 含 `I`（2′-O-甲基肌苷）的真实化学字母表 ④ 缺注释的输入应**报错而不是静默算错** ⑤ Vutrisiran 分子式反推一致性。①是唯一有手算对照的——这就是今天练习的价值。
</details>
