# 踩坑：ViennaRNA 2.7+ 的 RNAplfold 默认不产 lunp 文件

| | |
|---|---|
| 日期 | 2026-11-12（D21 B3，服务器 RNAplfold 2.7.2） |
| 损失 | 约 1 h 排查（两次"卡住"+ 一次无效验证） |

## 现象

`RNAplfold -W 80 -L 40 < ttr.fa` 正常结束、产出 `<prefix>_dp.ps`，但**没有** `<prefix>_lunp`。
解析器等 lunp 不到 → `test_scan_sites.py` 的 I1 冒烟测试段表现为挂起/无输出。

## 根因

ViennaRNA 2.7 起默认只产 `_dp.ps`；**`_lunp` 必须显式 `-u <L>`**（--ulength：长度 1..L 区域未配对概率）。
教程和旧文档（多为 2.4/2.5 时代）都写"lunp 默认输出"——版本差异陷阱。

## 修复

```python
cmd = ["RNAplfold", "-W", "80", "-L", "40", "-u", "1", "-O"]
```

- `-u 1`：单碱基 P(unpaired)，输出的 lunp 格式恰为 `pos + 一列概率`（# 表头），解析器不用改
- `-O`：不产 dp.ps（对位点扫描无用，白占空间）
- FASTA 从 **stdin** 喂（`stdin=open(fasta)`），比位置参数兼容性好

## 排查中顺带确认的三条

1. **prefix 来自 FASTA 头行首词**（stdin 方式下）：`>NM_000371.4 ...` → `NM_000371.4_lunp`。目录里的 `NM_000371.4_dp.ps` 就是这么来的，可当"跑过"的证据读。
2. **序列短于 -W 窗口时无 lunp**（WARNING: window size larger than sequence length）——小片段/短 RNA 没有可及性定义，v1 处理 5′UTR 片段时要记得。
3. **多行命令粘贴会被折行**，`#` 注释把后面的命令全部吞掉——"命令没跑但提示正常"，又一个静默出错变体。诊断时逐行执行、去掉行内注释。

## 可迁移判据

**工具的输出文件清单要看 `--help`，不要信教程**——教程写的是它那个版本的行为。
