## 这个坑（2026-10-30，D8 查漏日发现）

- **现象**：转型计划文档里写的参考文献 `Damase et al. 2022` —— 去 Europe PMC 按作者 + 年份检索，**返回 0 条**。
- **当时的错误理解**：一度以为是自己检索式写错了（加了错误的语法），反复改 query 浪费了几分钟。
- **正确结论**：**信息源本身就错了，不是检索方式错了。**
  | | 文档里写的 | 实际 |
  |---|---|---|
  | 年份 | Damase et al. **2022** | **2021** |
  | 标题 | （原计划没收全，一度误记为别的标题） | 《The Limitless Future of RNA Therapeutics》 |
  | 期刊 | *Front Bioeng Biotechnol* ✅ | 卷 **9**，Frontiers Media ✅ |
- **代价**：十几分钟返工；更麻烦的是这个二手引用被我用了好几天，差点把错的参会文献引用码。
- **怎么避免**：
  1. **文献引用一律用 PMID / DOI 反查一遍元数据**（Europe PMC REST API 或 PubMed 皆可），不要靠手写"人名 + 年份 + 标题"。
  2. 宁可在表里存一个数字 ID，也不要存一段自由文本的引用字符串。
  3. **搜不到 ≠ 你搜错了** —— 与更正 C2（openFDA 查不到 pegaptanib → 实际是药物已撤市）是同一类信号，这是第三次踩同一个思维模式。

## 举一反三（这条已经变成一个通用检查）

| 场景 | 直觉反应 | 正确反应 |
|---|---|---|
| openFDA 查不到某药 | "我写错参数了" | **可能是该药已撤市**（C2） |
| Europe PMC 查不到某文献 | "我 query 写错了" | **可能是记错了年份/标题/作者**（C4） |
| 脚本在某个药物序列上崩了 | "数据有错" | **可能字母表不含修饰碱基**（plozasiran 含 I） |

> 三次教训的共性：**先怀疑输入（信息源/数据），再怀疑自己。** 这与 C1/C3（结构细节必须回 FDA label 原文）同源 —— 二手信息的错。
