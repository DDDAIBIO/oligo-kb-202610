# 20261112 · 解析器把非法输入静默降级（第一次 code review 的头号问题）

> 时间：2026-11-12 ｜ 场景：`oligo_decorate.py` 的 `parse_notation()`（D16 产出、D21 收尾）
> 类型：静默错误（不报错、结果看起来正常）｜ 严重度：🔴 会算错数

## 现象

21 条验收断言全绿之后，喂三个非法输入：

| 输入 | 期望 | 实际（原实现） |
|---|---|---|
| `Am*C` | 报错（`m` 前缀没跟碱基就遇到 `*`） | **静默返回 `(['A','C'], 1)`** —— `m` 被吞掉 |
| `mmC` | 报错（前缀只允许单字符） | 静默返回残基 `"mmC"` |
| `dmC` | 报错 | 静默返回残基 `"dmC"` |

## 根因（两处，同一个思维漏洞）

```python
if ch == "*":
    ps += 1
    buf = ""          # ← 问题 1：未完成的前缀被直接清空
...
if buf and buf[-1] not in VALID_PREFIX:   # ← 问题 2：只校验最后一个字符
```

1. `*` 分支把 `buf` 清空，没检查它是否非空 → **输入里的字符被无声删除**。
2. `buf[-1] in VALID_PREFIX` 只看末字符 → `mm`、`dm` 都能过，因为末字符是合法前缀。

## 为什么危险（比崩更糟）

- `Am*C` 被读成 `A-C`：少一个 2′-OMe、PS 位置也错了。报告照常打印，**数字看起来完全合理**。
- `mmC` 生成的 `"mmC"` 会流到下游 `summarize_residues`，是崩还是算错取决于下游实现——**错的传播路径不可控**。
- 与 D20 的「SNP 掩蔽坐标翻转」同一类事故：**不报错的错，是最贵的错**。

## 修法（两行判据）

```python
if ch == "*":
    if buf:
        raise ValueError("位置 %d: * 前有未完成的前缀 %r" % (i, buf))
...
if buf and buf not in VALID_PREFIXES:      # 整个 buf 必须是合法前缀，不是末字符
    raise ValueError("位置 %d: 非法前缀 %r" % (i, buf))
```

## 可迁移的判据（下次写任何解析器都先问）

1. **清空缓冲区的地方，必须先断言它是空的**（`buf = ""` 前一行永远该有个 `if buf: raise`）。
2. **校验"词法单元"要校验整体，不要校验首/末字符**——`buf[-1]`、`s.startswith` 这类写法只配做快速预筛。
3. **反向测试比正向测试更能说明质量**：21 条正向断言全绿，三个非法输入就露了。
4. **非法输入的选择偏好：报错 > 修正 > 忽略**。凡是选"忽略"的地方，写一行注释说明为什么安全。

## 附带发现（同类，未修）

`parse_notation` 只返回 PS **数量**，不返回**位置**。而 D15 冻结的 9 个特征是「PS 数量**与分布**」——位置信息在解析层就丢了，导致 `test_expected.py` 里不得不自己重扫一遍字符串还原位置（重复逻辑 = 未来的分叉点）。

修法：`parse_notation_full()` 返回 `{residues, ps_links, ps_positions}`，原 `parse_notation()` 保留两元组做兼容包装。回归验证：T0–T5 输出与原实现完全一致。
